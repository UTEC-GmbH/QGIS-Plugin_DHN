  * Create a symbolic link between repo and QGIS plugins folder

    Open Command Prompt as an Administrator.
    Create the symbolic link using the "mklink /D" command. 

    The format is: mklink /D <Link_Path> <Target_Path>

    where "Link_Path" is the path to the plugin folder in the QGIS profile of choice ("_dev" suffix)
        (in QGIS: Settings → Userprofile → open profile folder → python → plugins)
    and "Target_Path" is the path to the folder where the development of the plugin takes place (Git repo)

    mklink /D "C:\Users\**USER_NAME**\AppData\Roaming\QGIS\QGIS**X**\profiles\default\python\plugins\**PLUGIN_NAME**_dev" "C:\**DEV_DIRECTORY**\**PLUGIN_NAME**"
    mklink /D "C:\Users\Florian\AppData\Roaming\QGIS\QGIS3\profiles\default\python\plugins\UTEC_Layer_Tools_dev" "C:\Github_Repos\QGIS-Plugin_Layer_Tools"


  * Translation Workflow
    
    Compile the Translation by running compile.bat (found in the root directory) 
    in the OSGeo4W Shell. 
      - Open the OSGeo4W Shell (from the Windows start menu)
      - `cd **PATH_TO_PLUGIN**`
      - `compile.bat`

    This finds all the strings to translat in the code and 
    opens linguist so the translations can be edited. 
    After closing linguist, it will compile the translations.

    If linguist doesn't open or lrelease is not installed, 
    go to OSGeo4W setup and install "qt6-devel" (in the "Libs" section)


  * Publishing New Versions

    1. Update the `version` number and changelog in `metadata.txt`. 

    2. Run the release script from the OSGeo4W Shell in the plugin directory 
       using the following commands:
       
      `cd **PATH_TO_PLUGIN**`
      `python release.py`

      Running without arguments displays a menu for the default release,
      choosing a custom output directory, committing, or pushing.
       
      This script will update `plugins.xml` and package the new .zip file.
      The .zip file and plugins.xml will be saved to the server 
      (see `download_url_base` in metadata.txt).

      To automatically create a local Git commit for those generated files,
      run `python release.py --commit` instead. This commits only the plugin
      .zip file and `plugins.xml` in the release repository; it does not push.

      To commit and push the release branch to its configured upstream, run
      `python release.py --push`. This requires an upstream to be configured
      for the current branch; it does not select or switch branches.
